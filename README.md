# Sales & Profit Report | Power BI

An interactive Power BI portfolio project for analyzing sales performance, profitability, refunds, and customer purchasing patterns across products, categories, countries, payment methods, and time.

## Project Overview

The goal of this project is to build an interactive sales analytics report that allows users to monitor business performance and investigate how revenue moves from initial order value through discounts, income, costs, profit, and refunds.

The report supports analysis by:

- Order date
- Product
- Product category
- Country
- Payment method

It also includes a Sankey diagram to visualize the flow of order value from product categories through the major financial components of each transaction.

## Business Problem

A retail business needs a simple way to understand not only how much it sells, but also how those sales translate into actual income and profit.

The report is designed to answer questions such as:

- How are orders changing over time?
- Which product categories generate the most sales?
- What is the average income per order?
- How significant are refunds?
- How do discounts, taxes, fees, profit, and refunds contribute to the overall order value?
- How does performance differ across products, countries, and payment methods?
- How does the selected period compare with the previous period or the same period last year?

## Data Model

The Power BI model contains four main tables.

### `powerbi_orders_20000`

The main fact table containing order-level sales data.

### `Calendar`

A dedicated date dimension used for time filtering and time-intelligence calculations.

Relationship:

```text
Calendar[Date]  1 ───────── *  powerbi_orders_20000[order_date]
```

The Calendar table is created dynamically from the minimum and maximum order dates:

```DAX
Calendar =
CALENDAR(
    MIN(powerbi_orders_20000[order_date]),
    MAX(powerbi_orders_20000[order_date])
)
```

### `Sankey Flows`

A calculated helper table used to transform the order-level dataset into source → destination relationships required by the Sankey visual.

Relationship:

```text
powerbi_orders_20000[order]  1 ───────── *  Sankey Flows[order]
```

The table models the following financial flow:

```text
Product Category
       ↓
   Full Price
       ↓
 ┌─────────────┐
 Discount    Income
               ↓
     ┌─────────┼─────────┬─────────┐
    Tax       Fee      Profit    Refunds
```

For refunded transactions, the original transaction value is reconstructed from the refund amount so that refunded orders remain represented correctly in the Sankey flow.

The calculated table uses DAX functions including:

- `SELECTCOLUMNS`
- `UNION`
- `FILTER`
- `IF`

### `Parameter Selector`

A disconnected field-parameter table used to dynamically change the metric displayed in the main chart without requiring separate visuals for every measure.

This allows one chart to respond to the metric selected by the user.

## Main KPIs

The report focuses on several core sales and profitability metrics.

### Orders

Tracks the number of orders within the current report filter context.

### Income

Represents sales value after discounts.

### Profit

Represents income remaining after taxes and processing fees.

### Refunds

Tracks the value returned to customers from refunded transactions.

### Average Income per Order

Measures the average income generated by an order.

```DAX
_Avg. Income =
DIVIDE(
    [_Income],
    [_Orders]
)
```

### Average Refund per Order

Shows the average refund value based on the current report context.

Together, these KPIs provide a compact view of transaction volume, revenue generation, profitability, and refund activity.

## DAX Highlights

The project uses DAX for KPI calculations, time intelligence, dynamic comparisons, calculated tables, and interactive report behavior.

### Average Income

Rather than averaging the `income` column directly, the calculation uses total income divided by the number of orders.

```DAX
_Avg. Income =
DIVIDE(
    [_Income],
    [_Orders]
)
```

Using `DIVIDE()` also safely handles cases where the denominator is zero.

### Average Income — Last Year

The report includes year-over-year comparison using the Calendar dimension.

```DAX
_Avg. Income LY =
CALCULATE(
    [_Avg. Income],
    DATEADD(
        'Calendar'[Date],
        -12,
        MONTH
    )
)
```

This shifts the current filter context back exactly 12 months while preserving the selected reporting period.

### Average Income — Previous Period

A dynamic previous-period measure determines the duration of the currently selected period and automatically calculates the equivalent period immediately before it.

```DAX
_Avg. Income Previous Period =
VAR CurrentStart =
    MINX(
        ALLSELECTED('Calendar'[Date]),
        'Calendar'[Date]
    )

VAR CurrentEnd =
    MAXX(
        ALLSELECTED('Calendar'[Date]),
        'Calendar'[Date]
    )

VAR PeriodMonths =
    DATEDIFF(
        CurrentStart,
        CurrentEnd,
        MONTH
    ) + 1

VAR PreviousStart =
    EDATE(
        CurrentStart,
        -PeriodMonths
    )

VAR PreviousEnd =
    CurrentStart - 1

RETURN
    CALCULATE(
        [_Avg. Income],
        REMOVEFILTERS('Calendar'),
        DATESBETWEEN(
            'Calendar'[Date],
            PreviousStart,
            PreviousEnd
        )
    )
```

For example, if a user selects a three-month period, the measure automatically compares it with the preceding three months.

This makes the calculation responsive to the date slicer rather than relying on a fixed month-over-month comparison.

## Order Value Flow

One of the key analytical features of the report is the **Order Value Flow** Sankey diagram.

Instead of displaying sales figures independently, it visualizes how transaction value moves through different financial stages:

```text
Product Category
        ↓
    Full Price
      ↙     ↘
Discount   Income
             ↓
     Tax / Fee / Profit / Refunds
```

This makes it possible to visually compare gross order value with discounts, operating deductions, retained profit, and refunded amounts.
